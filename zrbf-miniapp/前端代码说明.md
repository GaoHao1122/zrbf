# 前端代码说明（零基础版）

这份文档用大白话解释整个前端工程是怎么组织的，方便没有编程基础的人也能看懂“代码放在哪、每部分在干什么”。

## 1. 这个项目是干什么的

这是一个微信小程序，帮用户记录每天买彩票花了多少钱、中了多少钱，并自动算出是赚还是亏，再用图表展示最近一段时间的变化。

程序里的核心逻辑只有一个公式：

```text
净盈亏 = 中奖金额 - 投入金额
```

如果结果是正数就是“盈利”，等于 0 就是“持平”，负数就是“亏损”。

## 2. 打开小程序后发生了什么

1. 小程序启动，`src/App.vue` 里的代码先执行。
2. 它检查本地有没有登录凭证（Token）。
3. 没有的话就调用微信登录（`uni.login`），拿一个 code 发给后端，后端返回 Token 和用户信息。
4. 进入首页 `src/pages/dashboard/index.vue`，请求 `GET /api/v1/dashboard`，展示今日盈亏、累计统计和趋势图。
5. 用户点击“今日登记”，进入 `src/pages/lottery/add.vue` 填写投入和中奖金额，保存后后端会返回当天最新的聚合结果。
6. 首页“历史记录”列出每天的主记录，点进去是当天的明细，可以编辑、删除或清空。
7. “趋势分析”页可以切换周/月/年，查看折线图和每一天/月的盈亏。
8. “我的”页展示用户信息和累计统计，可以退出登录。

## 3. 目录结构怎么看

代码全部放在 `src/` 下面，按职责分文件夹：

```text
src/
├── api/        接口层：告诉程序“后端有哪些接口、怎么调用”
├── pages/      页面层：用户看到的每个屏幕
├── components/ 组件层：可复用的界面零件（卡片、徽章、图表）
├── stores/     状态层：多个页面共享的数据（登录用户、历史记录）
├── utils/      工具层：格式化金额、校验输入、读取 Token 等
├── types/      类型层：和后端约定的数据长什么样
├── styles/     样式层：全局颜色、字号、间距
├── App.vue     应用入口
├── main.ts     创建应用（注册 Pinia）
├── pages.json  页面路由和底部 TabBar 配置
├── manifest.json 小程序平台配置
└── uni.scss    全局 SCSS 变量
```

### 数据流向

```text
页面（pages）
  ↓ 调用
状态（stores）或直接调用接口
  ↓ 调用
接口层（api）
  ↓ 通过 request.ts
后端 Spring Boot 服务
```

所有接口请求都经过 `src/api/request.ts`，它会自动带上 Token、处理错误、显示加载提示，所以其他页面不需要重复写这些逻辑。

## 4. 每个模块是干什么的

### 接口层 `src/api/`

| 文件 | 作用 |
| --- | --- |
| `request.ts` | 请求封装：统一地址、Token、错误提示、401 处理 |
| `user.ts` | 微信登录、获取用户资料 |
| `lottery.ts` | 新增、查询、修改、删除彩票记录 |
| `statistics.ts` | 今日 / 周 / 月 / 年统计 |
| `dashboard.ts` | 首页聚合数据 |
| `chart.ts` | 趋势图数据 |

### 状态层 `src/stores/`

| 文件 | 作用 |
| --- | --- |
| `user.ts` | 登录用户、Token、退出登录 |
| `lottery.ts` | 今日记录、历史列表（翻页时合并数据） |
| `app.ts` | 全局加载标记（预留） |

### 组件层 `src/components/`

| 组件 | 作用 |
| --- | --- |
| `StatCard` | 统计数字卡片（例如“今日投入”） |
| `StatusBadge` | 盈利 / 持平 / 亏损 状态标签 |
| `DetailItem` | 一条彩票明细的展示与编辑/删除按钮 |
| `EmptyState` | 没有数据时的空状态提示 |
| `TrendChart` | ECharts 折线图（封装了 canvas 初始化） |
| `ProfitRing` | 收益率环形图 |
| `MoneyInput` | 金额输入框（带 ¥ 前缀，限制两位小数） |
| `Skeleton` | 加载中的灰色占位骨架 |
| `LoadMore` | 列表底部“加载中 / 没有更多了” |

### 工具层 `src/utils/`

| 文件 | 作用 |
| --- | --- |
| `auth.ts` | Token 和用户信息的本地存取 |
| `format.ts` | 金额、日期、百分比格式化 |
| `validate.ts` | 表单校验规则 |
| `constants.ts` | 盈亏状态、彩票类型、趋势 Tab 常量 |
| `platform.ts` | 判断当前是微信小程序还是 H5 |

## 6. 数据是怎么来的

前端本身不保存业务数据，全部来自后端接口。接口的字段定义在 `src/types/api.ts`，和项目根目录 [6.接口设计.md](../6.接口设计.md) 以及后端 `dto/response` 对齐。

例如首页调用的接口：

```text
GET /api/v1/dashboard
```

返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "today": { "investAmount": 20, "netAmount": -20, "profitRate": "-100%", "status": "LOSS" },
    "summary": { "totalInvestAmount": 3000, "totalProfitAmount": 500, "totalNetAmount": -2500, "winRate": "35%" },
    "chart": { "type": "week", "data": [{ "x": "08-01", "y": 100 }] }
  }
}
```

## 7. 怎么改代码

常见需求对应位置：

- 改首页布局 → `src/pages/dashboard/index.vue`
- 改登记表单 → `src/pages/lottery/add.vue`
- 改颜色和字号 → `src/styles/tokens.scss`
- 新增接口 → 在 `src/api/` 新建文件，并在 `src/types/api.ts` 加类型
- 新增页面 → 在 `src/pages/` 建目录，并在 `src/pages.json` 注册
- 修改请求逻辑 → `src/api/request.ts`

## 8. 常见问题

### 页面请求失败

先确认 `.env.development` 里的 `VITE_API_BASE_URL` 是不是后端地址；小程序预览时要在微信开发者工具里关闭“合法域名校验”。

### 登录不成功

开发阶段默认走 mock 登录：后端 `application.yml` 里 `wx.miniapp.mock-login` 默认为 `true`，未配置真实微信 AppID/Secret 时，登录接口直接返回固定开发用户，不需要真实微信号。配置真实 `WX_APPID` / `WX_SECRET` 后设置 `WX_MOCK_LOGIN=false` 即可切换为真实微信登录。

### 图表不显示

需要先安装依赖（`pnpm install`），且后端趋势接口要有数据；没有数据时组件会显示“暂无趋势数据”。

### 图标不显示

TabBar 图标在 `src/static/icons/tab/`，构建时会一起打包，确认文件存在即可。

## 9. 与后端配合的约定

- 接口前缀统一 `/api/v1`
- 统一返回 `{ code, message, data }`
- 需要登录的接口通过 `Authorization: Bearer <token>` 传递身份
- `code=401` 时前端自动清空登录态并回到首页
